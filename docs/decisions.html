Architecture Decision Records

Short, dated records of decisions that shape the project. Each records the context, the decision, and its consequences. Superseding a decision means adding a new ADR, not editing the old one.

ADR-0001 — Treat the CPAPI and IB REST surfaces as distinct

The single OpenAPI document describes 185 operations that belong to two different API surfaces: /v1/api/* (CPAPI, ssoBearer) and /gw/api/* (IB REST, oauth2Bearer). Model them as distinct with surface-specific clients.

ADR-0002 — Two auth models: ssoBearer and oauth2Bearer

Model authentication per surface with a common CredentialProvider interface. v1 implements only ssoBearer; the SDK never accepts or stores a username/password.

Read full ADR →

ADR-0003 — Generate types/client with oapi-codegen + spec patching

Hand-writing ~443 schema types is infeasible. Generate with oapi-codegen, apply deterministic patches via scripts/patch_spec.py, commit generated code, verify reproducibility.

Read full ADR →

ADR-0004 — Minimal dependency set

An SDK is imported transitively by its users. Keep the runtime dependency set minimal and justified: coder/websocket, x/time/rate, oapi-codegen/runtime. No web frameworks, no DI frameworks.

ADR-0005 — v1 targets the CPAPI surface only

v1 implemented only CPAPI (ssoBearer). As of commit 48bdde6, all 185 operations are implemented. Superseded by ADR-0011 which added the OAuth2 surface.

ADR-0006 — Context-aware, channel-based API; use coder/websocket

Use github.com/coder/websocket for streaming — first-class context.Context, safe concurrent writes. Expose streaming as channel-based Subscription values with Updates() and Errors() channels.

ADR-0007 — License under Apache-2.0 with DCO

Apache License 2.0 with full canonical text. SPDX headers on all files. DCO sign-off on every commit (git commit -s); no CLA.

ADR-0008 — Money and quantities are never float64

IBKR returns monetary values as JSON strings to preserve precision. Represent money, prices, and quantities as string or json.Number — never float64.

Read full ADR →

ADR-0009 — Never auto-retry order mutations

IBKR order endpoints are not idempotent. Resubmitting after timeout can create duplicate orders. Retry only safe methods (GET/HEAD/OPTIONS); order mutations are never retried automatically.

Read full ADR →

ADR-0010 — Project naming and module path

Module path: github.com/shing1211/ibkrapi4go. Go package: ibkr. Display name: ibkrapi4go everywhere in docs.

ADR-0014 — In-repo mock IBKR gateway

internal/mockgateway serves both API surfaces from a single handler. Covers all 185 operations. Scriptable faults, deterministic values, request recording. Ships as standalone binary.

ADR-0015 — Public API surface and stability contract

The public API is all exported symbols in pkg/ibkr/. Stability levels: Stable, Experimental, Internal. Pre-1.0 semver rules apply until v1.0.0.

Read full ADR →

ADR-0016 — Error handling philosophy

*ibkr.Error for remote API failures; *ibkr.ConfigError for invalid configuration. 11 sentinel errors. Errors wrap with %w for errors.Is/errors.As.

Read full ADR →

ADR-0017 — Logging interface

Use stdlib log/slog. Seven subsystems with distinct keys. Credentials and request bodies are never logged. DebugInfo() returns a safe snapshot.
